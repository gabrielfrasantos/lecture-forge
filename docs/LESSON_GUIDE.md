# Lesson production guide

How to build one lesson of a lecture-forge series, end to end, to the standard of the PMSM & BLDC pilot
(`series/pmsm-bldc/01-compass-to-motor`). Read the pilot's `script.py`, `scenes.py` and `thumb.py` before starting:
they are the reference implementation.

## 1. The viewer and the brief

- Viewer: an engineer with solid maths (calculus, vectors, linear algebra, ODEs) who is new to motor physics.
  Goal: intuition strong enough to derive equations, predict behaviour and interpret measurements.
- Pattern for every lesson: **observation → physical model → mathematical derivation → motor consequence → practical prediction**.
- Visual style in the spirit of 3Blue1Brown: build the picture first, then the equation; animate the idea
  (vectors adding, a field forming, a frame rotating) rather than showing static slides. Slow, purposeful camera.
- Every lesson includes at least one **practical measurement** (bench) or **simulation exercise** the viewer can do,
  shown concretely (what to connect, what to expect, what numbers).
- Say where each simplified model stops applying, on screen and in the narration.
- End with three prediction questions (stored in `META["predictions"]`) and a one-sentence transition to the next lesson.
- Open with a short hook. If the previous lesson asked a prediction this lesson can answer naturally, answer it in
  one or two sentences early on.
- Length: 5–8 minutes, about 750–1150 spoken words, 10–14 scenes (each scene = one chapter).

## 2. Narration

- Write for speech: contractions, connected sentences, transitions that say why the next idea follows.
  Sounds like an engineer explaining an experiment to another engineer. No hype, no promotional tone, no bullet lists read aloud.
- Read equations as meaning ("B of r is mu-nought I over two pi r") while the screen shows the notation.
- Each beat = (id, caption text, spoken text or None, pause after). Caption text is what viewers read (with symbols
  like μ₀, ×, ²); the spoken text is respelled for the voice.
- Pronunciation rules learned on the pilot:
  - Single-letter variables: use letter phonemes, e.g. `[a](/ˈA/)`, `[x](/ˈɛks/)`, otherwise "a" and "x" vanish.
  - Say "I times [dl](/dˌiˈɛl/)", never "I d-l" (heard as "ideal").
  - Names: add to `LEXICON` in script.py (misaki phonemes). Check with
    `cd <lesson> && PYTHONPATH=.:../common:../../../core python3 ../../../core/asr_try.py "sentence"`.
  - Prefer "the axis of a coil" over "a coil's axis" (heard as "quail's").
- Whisper round-trip (forge `qc`) target: word error rate < 10 %, with remaining differences only numerals vs words,
  possessives, sine/sign homophones. Fix and re-voice anything else.

## 3. Accuracy

- Every number on screen is computed in code (lesson `physics.py` or `series/<series>/common/physics.py`) and checked
  with `assert`s: directions by the right-hand rule, signs of torque, units, limiting cases, a numerical method
  against a closed form when one exists.
- Every historical claim is checked against sources you actually opened (museums, original publications, university
  pages; WebSearch + WebFetch). Put them in `META["sources"]`. Mark reconstructions with the HISTORICAL badge.
  Do not repeat myths; when a date is traditional only, say so.
- Figure badges (top right, every scene): `calc` (CALCULATED / SIMULATED), ANALYTIC (`calc` colour), `schem`
  (SCHEMATIC), `hist` (HISTORICAL RECONSTRUCTION), `meas` (MEASUREMENT, for bench data or bench procedure).
  The badge text states the model in a few words (e.g. "CALCULATED · 2D finite-difference magnetostatics, linear iron μr = 2000").
- Never present a decorative field as a finite-element result. If you compute a field numerically (FD, FEM), say which
  method, mesh/grid and material assumptions, and check it against an analytic case.
- Field-line arrowheads are static and show direction only; never animate them as particles flowing.
- Before rendering, do an adversarial review of your own script: re-derive every equation, re-check every number and
  sign in code, and ask "would a demanding motor-design professor object to any sentence?" Fix what you find.

## 4. Files in a lesson folder

```
series/<series>/<NN-slug>/
  script.py   META (slug, title, series, lesson, voice, speed, youtube_title ≤ 100 chars, youtube_summary,
              predictions, sources), LEXICON, SCENES = [(scene_id, chapter title, lead-in s, [beats])]
  scenes.py   from scenekit import *; one Scene subclass per entry in SCENES, same order; SCENE_CLASSES = [...]
  thumb.py    HEADLINE (≤ 5 words over 1–3 lines), HIGHLIGHT, ACCENT, LESSON, KICKER, hero(ax)
  physics.py  (optional) lesson-specific calculations with self-checks under `if __name__ == "__main__":`
  release/    generated by `forge.py release` and `forge.py thumb`; committed
  out/, cache/  generated, git-ignored
```
Shared code for a whole series goes in `series/<series>/common/` (importable from every lesson). Add new modules or new
functions there; do not change the behaviour of existing functions other lessons use. The same applies to `core/`.

## 5. Toolkit reference

- `engine.py`: canvas is 1920×1080 pixels, origin bottom-left. `C` palette. `Camera(target, az, el, dist, fov, cx, cy)`;
  `Scene3D(cam)` with `poly`, `mesh(faces, color, cull=, alpha=, bias=)`, `line`, `arrow`, `arrow_head_on_path`, `disc2d`,
  `draw(ax, z0)`. Mesh builders: `box`, `cylinder`, `tube`, `annular_sector`. Overlays: `text`, `eq(ax, x, y, latex, size,
  color, alpha, ha, va)` (real LaTeX via pdflatex, cached), `badge`, `chapter_tag`, `note`, `panel`, `leader`,
  `fade_overlay`. Timing: `ease(t, t0, dur)`, `window(t, t0, t1)`.
- `scenekit.py`: `Plot` (2D axes in pixel space), `arrow2d`, `mini_compass`, `label3d`, `circle_pts`, `orient_along`,
  and `Scene` (gives `self.dur`, `self.cue[beat]`, `self.cend[beat]`, `self.at(beat, phrase)`; override `setup()` and
  `draw(ax, t)`; set class attributes `num`, `title`, `badge_text`, `badge_kind`).
- Series common (`pmsm-bldc/common`): `models3d.py` (`motor_parts`, `compass`, `rect_coil`), `physics.py` (`MU0`,
  `wire_B`, `biot_savart`, `loop_segments`, `loop_B_exact`, `loop_axis_Bx`, `trace_loop_fieldlines`).
- Painter's algorithm: when parts draw in the wrong order, add `bias=` (positive = drawn earlier/behind), split long
  objects into segments, and use `cull=False` for thin double-sided parts.

## 6. Workflow (run from the repo root)

```bash
L=series/<series>/<NN-slug>
python3 forge.py $L audio                    # voice every beat (cached) -> timeline.json; prints scene durations
python3 forge.py $L still 3 12.5             # preview frame: scene 3 at t = 12.5 s -> $L/out/stills/
# contact sheet of 4 frames:  cd $L && PYTHONPATH=.:../common:../../../core python3 ../../../core/sheet.py name 1:5 2:7 3:9 4:2
python3 forge.py $L render 1 3 5 7 9 11 &    # two render processes use both CPUs
python3 forge.py $L render 2 4 6 8 10 12; wait
python3 forge.py $L captions && python3 forge.py $L master && python3 forge.py $L mux && python3 forge.py $L qc
python3 forge.py $L thumb && python3 forge.py $L release
```
- Look at stills at full size for every scene at its busiest moment before rendering: overlapping labels,
  text running off panels, labels on top of 3D parts, unreadable equations. Fix, then render.
- Keep essential content above y = 150 px (players draw captions there) and inside a 40 px margin.
- After re-voicing beats in one scene, copy `timeline.json` to `timeline_v1.json` before `audio`: later scenes then keep
  their exact frame counts and only the changed scenes need re-rendering.
- A full render takes roughly 20–40 CPU-minutes. Don't re-render everything for a one-scene fix.
- QC targets: −16 LUFS ±1, true peak ≤ −1 dBTP, A/V difference < 1 frame, captions ≤ 20 chars/s, no cue over silence,
  one chapter per scene, ASR WER < 10 %.
- Thumbnail: 3840×2160 JPEG < 2 MB (forge does this), headline ≤ 5 words, bottom-right corner empty (YouTube's duration
  badge), visual must match the lesson; advertiser-friendly (no profanity, shock, sexual or misleading content).
  Check `release/thumbnail_preview_320.png`: the headline must read at that size.

## 7. Git

- Work in your lesson folder. Commit only that folder plus any additive files in `common/` or `core/` you needed.
- Never commit MP4/WAV files or anything under `out/` or `cache/` (git-ignored).
- `git pull --rebase origin main` before `git push origin main`. Commit messages end with the attribution lines given to you.
